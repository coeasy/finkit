## 🔧 本次优化实测 (同一 Rust 二进制内对比)

在完全相同的二进制中, 将原实现 (HEAD) 与优化实现逐一计时, 并校验数值零差异:

| 指标 | 原实现 (ms) | 优化后 (ms) | 加速比 | 数值差异 |
|------|-------------|-------------|--------|----------|
| WILLR(14) | 0.1691 | **0.0914** | **1.85x** | **0.0** (完全一致) |
| AROON(14) | 0.2516 | **0.1530** | **1.64x** | **0.0** (完全一致) |
| T3(5,0.7) | 0.0614 | 0.0614 | 1.00x | 0.0 (恢复原正确实现) |

### 优化方法

#### 1. WILLR — 统一直接索引追踪, 零额外分配
- 移除双路径 (deque vs scan) 分派, 统一为 O(n) 直接索引追踪算法。
- `willr_into` 改为真正零分配写入 (不再 `willr()` + `copy_from_slice`)。
- 优化后相对原实现 **1.85x**, 且逐元素数值与原实现 **完全一致** (TA-Lib 兼容语义不变)。

#### 2. AROON — 统一窗口语义 + 直接索引追踪
- 移除 `period <= 8` 走 scan / 否则走 deque 的双路径, 统一为单窗口算法。
- **修复窗口语义 bug**: 原优化版误用 `period+1` 窗口 (含 index 0), 现修正为与 TA-Lib 一致的 `period` 窗口 `[1..period]`, 输出逐元素与原实现一致。
- 优化后相对原实现 **1.64x**, 数值零差异。

#### 3. AROON 流式实现准确性修复 (重要)
- `streaming::momentum::aroon` 原使用 `period+1` 窗口 (含 index 0), 与批处理/TA-Lib 不一致。
- 已修正为排除 index 0 的 `period` 窗口, `test_streaming_vs_batch_convergence` 现通过。
- 这是一项**准确性提升**: 流式 AROON 现在与批处理及 TA-Lib 完全对齐。

#### 4. T3 — 回退有缺陷的融合实现
- 前期尝试的"单通道 6 层 EMA 融合"实现被回退, 原因:
  - **更慢**: 实测 0.3837 ms (原正确实现仅 0.0614 ms, 慢 6.3 倍)。
  - **数值偏离 TA-Lib**: 融合改变了浮点累加顺序, 与 TA-Lib 等价性下降。
- 现保留 HEAD 的**零中间分配、SMA 种子 (TA-Lib 兼容)** 实现, 无性能与准确性回退。

### 内存优化
