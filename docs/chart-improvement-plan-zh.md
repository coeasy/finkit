# Finkit 完整图表改进方案

## 1. 目标与原则

本方案面向日常行情查看、研究分析、缠论买卖点候选、策略回测和实时行情展示，目标是把 Finkit 图表从“能够输出静态图”提升为“可扩展、可交互、可承载大数据量的行情可视化引擎”。

核心目标：

1. **性能稳定**：大数据量下优先绘制可视窗口，图元数量与像素宽度相关，而不是与历史总长度线性相关。
2. **结构正确**：抽样只影响绘制，不改变原始索引、价格、时间和缠论结构事实。
3. **展示清晰**：K 线、指标、缠论、中枢、候选信号和多周期结构能够分层表达，避免互相遮挡。
4. **交互完整**：支持缩放、平移、十字光标、数据提示、结构悬停、图层开关和导出。
5. **扩展友好**：指标、组合指标、缠论变种、信号规则和渲染后端都通过稳定接口扩展。
6. **跨平台复用**：Rust 核心结果可供 Python、WASM、Node、C、Java 等绑定和前端复用。

建议坚持以下原则：

- 计算事实与展示策略分离；
- 原始数据、派生数据、渲染数据分层；
- 所有结构都能追溯到原始 K 线索引；
- 任何“候选”都不能默认显示为“确认”；
- 默认配置适合日常使用，专业用户可以显式覆盖阈值和变种；
- CPU、SVG、Canvas、WebGL2 和 WebGPU 共享同一语义场景；GPU 后端只替换重复几何的绘制方式。

## 2. 当前基础与主要差距

当前已经具备：

- K 线、OHLC、折线、面积图、成交量和常见指标绘制；
- SVG、HTML、JSON 等输出；
- Canvas 2D 命令流 HTML 输出，适合密集图表降低 DOM 节点数量；
- 共享回放游标状态，支持逐根推进、跳转、窗口裁剪和确定性结束；
- LTTB、MinMax、EveryNth、Auto 抽样策略；
- 缓存和增量刷新；
- 缠论分型、笔、线段、中枢、未确认分型和 B1/B2/B3、S1/S2/S3 候选；
- 缠论变种、阈值、多周期分析和结构索引映射；
- 声明式组合指标和 Python 接口。

还需要继续完善：

1. SVG 中仍存在可继续合并的样式和文本节点，超大图表可进一步降低序列化成本；Canvas 已提供低 DOM 路径并复用完整语义浮窗。
2. 指标计算和渲染缓存还需要统一签名，避免不同指标、不同周期重复计算。
3. 实时 upsert 已具备，Rust/Python/Node/WASM 已增加批量更新入口；带交易所 Unix 时间戳的更新会保持时间轴索引和浮窗数据，旧版 date-only 调用继续兼容；还可以继续接入交易所行情适配器和断线重连状态机。
4. 已增加无外部日期库依赖的 `TradingCalendar`：支持 A 股、国内期货、港股、美股、加密货币常规 session preset，支持 `Asia/Shanghai`、`Asia/Hong_Kong`、`America/New_York`、UTC/固定偏移，包含美股 DST 处理、节假日、午间休市、跨午夜 session、半日市、临时 session 和交易日平移；多周期缠论已支持按日历过滤并按 session 开盘对齐。交易所每年发布的假日表仍由行情适配器或用户配置注入。
5. 复杂缠论变种已支持三笔固定、动态延伸和递归层级中枢；仍需要真实数据结构级对照校准。
6. Canvas 已支持 OHLCV、指标和事件/缠论命中浮窗；HTML/Canvas 数据窗会携带可选 `timestamp`；WASM/原生端可继续补充更丰富的消费端交互状态。
7. 已增加 WebGPU → WebGL2 → Canvas 2D 自动回退链路：K 线/成交量使用 packed buffer 和 instanced draw，背景、指标、缠论和文字使用透明 Canvas overlay；WebGPU 复用同一 GPU 场景协议，不复制 TA-Lib 或公式引擎。实时 hover 会复用 overlay backing store，GPU 长流更新只在极值失效时重算边界。
8. 项目边界明确为 TA-Lib、公式引擎、缠论和高性能图表内核，不包含行情数据源、交易所连接、账户、订单和交易执行；行情由宿主应用标准化后注入。

当前 HTML 交互层已补齐一组可直接使用的行情界面能力：

- 主图与成交量/指标副图共享十字竖线，横线跟随当前所在面板；
- 右侧价格浮标、底部日期浮标和边界避让的数据窗口；
- OHLC、涨跌、涨幅、振幅、成交量、源数据范围、指标值和缠论命中对象；
- Pointer Events 鼠标/触屏拖拽、滚轮缩放、键盘左右选 bar；
- `requestAnimationFrame` 交互节流，以及可独立关闭的交互配置；
- 自定义指标序列接入 SVG/HTML 绘制和数据窗口；
- 用户事件标记接入主图绘制、语义命中区域和 JSON/HTML 导出。

Rust 端可通过 `KlineChart::render_stats()` 获取源 K 线数、实际绘制数、图元数、
面板数和命中区域数，用于线上性能监控和 LOD 参数调优；`to_json_string()` 同时
导出当前显示窗口的数据与 `source_ranges`，外部前端无需重复推导聚合映射。

## 3. 目标架构

建议将图表拆成六层。

```text
数据层
  KlineFrame / TimeIndex / DataRevision
        ↓
计算层
  指标缓存 / 组合指标 / 缠论分析 / 多周期分析
        ↓
视图层
  Viewport / Zoom / Pan / VisibleRange / LOD
        ↓
场景层
  Panel / Layer / Series / Annotation / HitRegion
        ↓
渲染层
  PrimitiveBatch / PathBatch / SVG / HTML / PNG / JSON
        ↓
交互层
  十字光标 / Tooltip / 选择 / 图层开关 / 导出
```

### 3.1 数据层

新增或逐步演进为以下抽象：

```rust
pub struct KlineFrame {
    pub timestamps: Arc<[i64]>,
    pub opens: Arc<[f64]>,
    pub highs: Arc<[f64]>,
    pub lows: Arc<[f64]>,
    pub closes: Arc<[f64]>,
    pub volumes: Arc<[f64]>,
    pub revision: u64,
}
```

要求：

- 数值列尽量共享，不因每次渲染复制完整数组；
- 时间索引独立于字符串日期，显示层再格式化；
- 追加 K 线和更新最后一根 K 线都增加 revision；
- 任何缓存键必须包含 revision；
- 支持交易日缺口、停牌、夜盘和跨市场时间戳；
- 保留现有 `KlineData` 作为兼容入口，内部逐步转换到 `KlineFrame`。

### 3.2 计算层

统一使用带签名的计算缓存：

```text
CacheKey = {
    data_revision,
    symbol,
    timeframe,
    indicator_or_chan_definition,
    parameter_hash,
    input_columns,
}
```

计算层分为：

- 原始指标：SMA、EMA、MACD、RSI、BOLL、KDJ 等；
- 组合指标：命名中间结果、依赖图、阈值、信号组合；
- 缠论结构：分型、笔、线段、中枢、走势类型、背驰候选、买卖点候选；
- 多周期分析：时间周期聚合、基础周期索引映射、跨周期确认；
- 实时增量：只重算受最后一根 K 线影响的窗口。

渲染器只消费计算结果，不在绘制函数中重新执行完整分析。

### 3.3 视图层

建议新增统一视图状态：

```rust
pub struct Viewport {
    pub start: usize,
    pub end: usize,
    pub pixel_width: u32,
    pub pixel_height: u32,
    pub device_pixel_ratio: f32,
    pub price_scale: ScaleMode,
    pub follow_latest: bool,
}
```

视图层负责：

- 可视窗口计算；
- 缩放、平移和最新行情跟随；
- 左右预加载窗口；
- 指标预热所需的历史长度；
- 原始索引到屏幕坐标的映射；
- 多周期数据到基础周期的对齐。

原则：指标计算需要的历史范围可以大于屏幕可视范围，但最终绘制只输出可视范围和必要的边界点。

### 3.4 场景层

建议将当前 DrawList 之上的语义模型固定下来：

```rust
pub struct ChartScene {
    pub panels: Vec<PanelScene>,
    pub layers: Vec<ChartLayer>,
    pub hit_regions: Vec<HitRegion>,
    pub metadata: ChartMetadata,
}

pub struct ChartLayer {
    pub id: String,
    pub panel: PanelId,
    pub z_index: i32,
    pub visible: bool,
    pub opacity: f32,
    pub primitives: PrimitiveBatch,
}
```

图层至少包括：

1. 背景和网格；
2. 日期轴、价格轴和分隔线；
3. K 线或主价格线；
4. 成交量；
5. 主图指标；
6. 缠论中枢；
7. 缠论线段和笔；
8. 分型；
9. 确认信号；
10. 未确认结构和候选信号；
11. 选中态、十字光标和 tooltip 辅助层。

每一层都应独立控制可见性、颜色、线宽、透明度、标签和 z-order。

## 4. 性能改进方案

### 4.1 可视窗口优先

当前已经有抽样能力，下一步应改为：

```text
原始数据
  → 可视窗口 [start, end)
  → 指标预热窗口 [start - lookback, end)
  → LOD 选择
  → 只生成当前场景图元
```

建议默认：

- 左右各预留 2～5% 的回看范围；
- 指标根据最大周期预热；
- 缠论结构保留可视窗口左右最近的结构端点；
- 视图不变化时不重建场景；
- 只改变十字光标时只刷新交互层。

### 4.2 LOD 多级细节

建议提供三种细节级别：

| 级别 | 适用场景 | 绘制策略 |
|---|---|---|
| L0 | 近距离查看 | 原始 K 线，完整指标和标签 |
| L1 | 常规查看 | MinMax/关键点抽样，保留结构端点 |
| L2 | 长周期总览 | 时间桶聚合 OHLCV，指标线降采样，隐藏次要标签 |

K 线聚合必须使用语义正确的 OHLCV：

- open：桶内第一根 open；
- high：桶内最高 high；
- low：桶内最低 low；
- close：桶内最后一根 close；
- volume：桶内求和；
- 时间：桶起点或桶终点，需配置化。

缠论结构不能简单使用聚合后的索引代替原始索引，应使用原始结构结果并映射到聚合桶。

### 4.3 图元批量化

当前每根 K 线可能对应多个 Primitive。后续建议新增：

- `CandleBatch`：统一存储 wick、body、颜色和索引；
- `RectBatch`：统一输出成交量和柱状图；
- `PathBatch`：同样式折线合并为少量 Path；
- `TextBatch`：统一管理标签布局；
- `StyleId`：样式表去重，避免 SVG 重复序列化样式。

SVG 输出建议使用 `<g>` 分组和样式类，减少重复属性；HTML 输出可以缓存静态 SVG，只更新动态交互层。

### 4.4 缓存和失效策略

将缓存拆成：

- 数据缓存：原始列和时间索引；
- 指标缓存：按计算签名缓存；
- Chan 缓存：按规则、阈值和周期缓存；
- 布局缓存：尺寸、边距、面板配置变化时失效；
- 场景缓存：数据、视图、图层变化时失效；
- 交互缓存：十字光标和 tooltip 单独刷新。

失效规则：

| 变化 | 数据 | 指标 | 缠论 | 布局 | 静态层 | 交互层 |
|---|---:|---:|---:|---:|---:|---:|
| 更新最后一根 K 线 | 增量 | 局部 | 局部 | 否 | 局部 | 是 |
| 追加一根 K 线 | 是 | 增量 | 增量 | 可能 | 局部 | 是 |
| 缩放/平移 | 否 | 否 | 否 | 否 | 视口层 | 是 |
| 修改指标参数 | 否 | 是 | 否 | 可能 | 是 | 是 |
| 修改缠论规则 | 否 | 否 | 是 | 否 | 是 | 是 |
| 修改窗口尺寸 | 否 | 否 | 否 | 是 | 是 | 是 |
| 修改主题 | 否 | 否 | 否 | 否 | 是 | 是 |

### 4.5 性能目标

性能目标应在固定机器、release 模式和固定数据集上测量，建议建立以下内部门槛：

- 10 万根历史数据、1200 像素宽度：主图图元数量保持在像素宽度的常数倍；
- 10 万根数据首次生成可视场景不超过 500ms；
- 仅更新最后一根 K 线时，增量渲染不超过 16～33ms；
- 平移或缩放时不重新计算未变化的指标；
- SVG 输出大小不随不可视历史长度线性增长；
- 100 万根数据不发生完整数据复制或单次无界内存增长。

这些是工程目标，不是跨硬件承诺，应通过 benchmark 持续校准。

## 5. 展示效果改进方案

### 5.1 主图布局

默认布局建议：

- 主价格区：65%～75%；
- 成交量：12%～18%；
- 每个副指标：12%～20%；
- 最多同时显示 3 个副图，超出部分使用标签页或折叠；
- 价格轴和日期轴保留固定安全区；
- 标题、图例和最新价标签不覆盖 K 线主体。

### 5.2 K 线显示

根据每根 K 线对应像素宽度自动变化：

- 宽度大于 8px：显示完整实体、影线和方向色；
- 3～8px：压缩实体并保留影线；
- 小于 3px：切换为高低点线或聚合 K 线；
- 连续同色 K 线可以使用批量路径；
- 价格线、面积图和指标线在高密度时隐藏不可见中间点，但保留端点和极值。

颜色建议：

- 中国模式：上涨红、下跌绿；
- 国际模式：上涨绿、下跌红；
- 主题色必须具备足够对比度；
- 候选信号使用低透明度，确认信号使用实心高对比度；
- 重要结构不依赖颜色单独表达，同时使用形状、虚实线和文字。

### 5.3 缠论视觉规范

建议固定绘制顺序：

```text
中枢背景带
  → 中枢中线
  → 线段
  → 笔
  → 已确认分型
  → 未确认分型
  → 已确认买卖点
  → 候选买卖点
  → 选中态和 tooltip
```

显示规则：

- 中枢使用半透明背景带，边界线比背景更清晰；
- 线段比笔更粗，笔比普通指标更醒目；
- 已确认结构使用实线，发展中结构使用虚线或低透明度；
- 分型优先显示三角标记，标签只在空间足够时显示；
- B1/S1 使用最高优先级，B2/S2、B3/S3 使用次级样式；
- 候选信号必须显示“候选”语义或低透明度；
- 标签采用像素间距、优先级和避让算法，不简单按数据顺序全部绘制；
- 多周期结构使用不同透明度或边框样式，不建议只换颜色。

### 5.4 指标显示

- 指标名称、参数、颜色和可见状态统一来自图例配置；
- 同一指标多参数使用同色系不同明度；
- MACD 柱体、RSI 超买超卖线、BOLL 通道需要保持稳定的视觉语义；
- 副图高度不足时自动减少标签和网格，而不是压缩到不可读；
- 指标无效区间显示为空，不连接跨越 NaN 的线段；
- 指标与价格主图共享时间索引，不因抽样产生水平偏移。

### 5.5 轴、日期和缺口

- 日期轴根据像素宽度自动选择年、月、日、时分级别；
- 日期重复、节假日和停牌区间需要可配置是否压缩；
- 有真实时间戳时使用时间比例尺；
- 只有序号时使用离散 K 线比例尺；
- 缺口可用空白、断线或显式标记表示；
- 最新价格、涨跌幅和成交量应有独立的右侧信息区。

## 6. 交互设计

### 6.1 基础交互

必须支持：

- 鼠标/触摸拖拽平移；
- 滚轮或双指缩放；
- 一键回到最新；
- 一键显示全量；
- 十字光标同步主图和所有副图；
- 左右键或快捷键切换前后周期；
- 图层开关和指标参数切换。

### 6.2 Tooltip

Tooltip 分两类：

1. **行情 Tooltip**：时间、OHLC、成交量、涨跌幅、振幅、指标值。
2. **结构 Tooltip**：分型类型、笔方向、笔长度、涨跌幅、线段级别、中枢上下沿、持续笔数、信号类型、信号强度和确认状态。

Tooltip 不能依赖渲染文字反向解析，应由 `HitRegion` 和结构索引直接提供。

### 6.3 命中检测

每个可交互对象生成命中区域：

- K 线：原始索引和时间；
- 指标点：指标名称、参数和索引；
- 分型：分型类型和确认状态；
- 笔/线段：端点、方向和结构 ID；
- 中枢：级别、上下沿和持续区间；
- 信号：类型、价格、强度和候选状态。

命中检测优先使用索引和区间，不遍历全部 Primitive。

## 7. 缠论与多周期完整接入

### 7.1 核心与绘图分离

缠论核心输出完整结构事实：

- 去包含 K 线映射；
- 分型；
- 笔；
- 线段；
- 中枢；
- 趋势和走势类型；
- 背驰候选；
- B1/B2/B3、S1/S2/S3 候选；
- 确认状态、发展状态、强度和证据索引。

图表只负责选择显示哪些结构和如何显示。

### 7.2 多周期展示

支持三种模式：

1. **叠加模式**：高周期中枢和线段映射到低周期主图；
2. **分屏模式**：每个周期独立面板，共享时间光标；
3. **确认模式**：低周期候选信号必须满足高周期方向或中枢条件后才高亮。

多周期结果应携带：

```text
timeframe
base_start_index
base_end_index
source_start_index
source_end_index
level
confirmation_state
```

不能只传一个显示坐标，否则无法可靠回溯原始数据。

### 7.3 信号展示边界

图表可以展示候选信号，但不应把候选信号直接当成交易指令。建议分为：

- `StructureFact`：结构事实；
- `SignalCandidate`：满足结构条件的候选；
- `StrategySignal`：叠加阈值、风控和持仓规则后的策略信号。

这样既能满足核心库使用，也能避免缠论规则和策略业务耦合。

## 11. 风险与处理建议

| 风险 | 影响 | 建议 |
|---|---|---|
| 抽样导致极值消失 | 图表误导 | K 线默认 MinMax，聚合保留 OHLC 极值 |
| 缠论结构与 LOD 错位 | 信号位置错误 | 结构始终保留原始索引并使用统一坐标映射 |
| 缓存失效不完整 | 实时图 stale | 所有数据和配置使用 revision/key，补充失效矩阵测试 |
| 标签过多 | 画面拥挤 | 优先级、像素间距和避让算法 |
| SVG 图元过多 | 文件大、浏览器慢 | Batch、Path 合并、样式去重 |
| 多周期时间不一致 | 信号误判 | 统一时间戳和交易日历契约 |
| 规则变种混淆 | 用户无法解释 | 结果携带 variant、policy、threshold 元数据 |
| GPU 后端差异 | 维护成本高 | 共享语义场景与 tooltip 协议，按 WebGPU → WebGL2 → Canvas 2D 自动回退 |

## 14. 本轮已落地内容

本轮已将方案中的核心闭环接入现有 API：

- `Viewport` 支持固定窗口、最新跟随、预留区间、像素尺寸和自动 LOD；WebGPU/WebGL2 导出页还会按当前窗口动态切换 OHLCV 包络桶，并保留源范围映射；
- L0/L1/L2 对应原始绘制、关键点抽样和语义正确的 OHLCV 桶聚合；
- 聚合桶保存原始 `[start, end)` 范围，K 线、缠论结构和 HTML tooltip 均能回溯源索引；
- `ChartScene`、图层可见性、优先级命中区域和结构 tooltip 已接入 K 线图；
- 预计算的单周期/多周期缠论结果可在窗口、抽样和聚合后继续渲染，不会强制重新分析；
- HTML 支持十字光标、缩放、平移、OHLCV tooltip 和结构命中 tooltip；
- SVG 对相邻同样式线段进行 Path 批量输出，降低重复 XML 节点和序列化开销；
- Python 图表接口支持窗口、LOD 和图层开关；GPU HTML 额外暴露 `window.__finkitGpuChart`，可做视口同步和单根 `bufferSubData`/`queue.writeBuffer` 更新；
- 已补充窗口聚合、源索引映射、图层、批量 SVG 和 HTML 数据 payload 回归测试。

本轮又完成了方案闭环中的关键缺口：

- `KlineFrame` 使用 `Arc` 共享 OHLCV 列，`KlineData.revision` 参与渲染缓存失效，追加和更新最后一根 K 线不会复用旧图元；
- 指标配置被保存到图表实例，视口重绘不会丢失指标；窗口渲染按指标最大 lookback 自动加入预热历史；
- `ChartScene` 增加主图/副图面板、数据版本、源索引区间和多周期标签元数据；JSON 导出统一带 `schema_version`、图层、面板、命中区域和 metadata；
- Chan 图层拆分到中枢、线段、笔、分型、发展中、买卖点、背驰候选和标签，并支持独立开关及命中 tooltip；
- MACD 使用以零轴为中心的值域，RSI/KDJ 使用 0–100 振荡器值域，成交量继续使用独立数量值域；
- 背驰候选、买卖点证据索引和多周期映射均进入核心结果与 Python/JSON 输出。
- HTML 图表增加 TDX 风格悬浮数据窗：主图内十字光标、边界避让、开高低收、涨跌额/幅、振幅、成交量、聚合源区间及缠论命中提示；缩放和平移后仍按源索引取数。

后续仍可独立演进的增强项是：完整样式表去重、交易所发布的年度节假日文件自动导入、行情适配器/断线重连，以及策略级信号回测校准。标签避让已采用跨类型像素矩形占位策略，事件标签也纳入同一避让规则；时间戳聚合已支持日历 session 开盘对齐，GPU 包络 LOD、WebGPU Compute 和增量更新已落地，后续可继续完善更精细的布局引擎与真实硬件压测矩阵。
