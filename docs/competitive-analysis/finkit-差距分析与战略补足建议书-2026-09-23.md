### 1.2 六维度详细论述

#### 维度一：发布与分发（G1，致命）

**根因**：项目把"多语言发布不是一个布尔值"（README.zh-CN.md）作为诚实性原则，但止步于 GitHub Release 资产，未推进 registry 发布。docs/language-bindings.md:319-320 明确禁止宣称 `pip install finkit` / `cargo add finkit` 可用——诚实但断绝了标准安装路径。

**影响**：所有竞品的获客第一入口都是 `pip install`。ta crate 停更留下的年 7.5 万下载真空（crates.io/crates/ta），finkit 因未上 crates.io 无法承接；kand（2026-01 加 WASM）正在填补同类位置。这是**当前投入产出比最高的单点改进**。

**竞品实现**：TA-Lib Python wrapper 在 PyPI（~9.9k stars）；Pandas TA Classic 0.8.32（2026-09-14）持续发版；quantstats/alphalens-reloaded 均标准 PyPI 分发。

#### 维度二：指标数量与口径（G2，致命）

**根因**：core/src/indicators/ 按 feature 分类发展，未与 TA-Lib 0.8.1（2026-09-12 新增 40+：SUPERTREND/HMA/ZLEMA/KDJ/VWAP/DONCHIAN/VORTEX/ERI）对齐增量；对外宣传"150+ indicators"（README.zh-CN.md）与公式层 314 函数（functions_legacy.rs:5481）口径割裂——用户无法回答"finkit 到底有多少能力"。

**影响**：数量是选型第一过滤器。Pandas TA Classic 用"284 个"作为核心宣传数字；finkit 在对比表中天然出局。且 finkit 的 streaming/ 中已存在 SUPERTREND/DONCHIAN/VORTEX 等实现（streaming/trend/supertrend.rs、volatility/donchian.rs、trend/vortex.rs），**只差命名对齐与 parity 契约**，属重复劳动浪费。

**竞品实现**：TA-Lib 0.8.1 CHANGELOG 每个新指标绑定 issue 与基准数据；Pandas TA 每版附指标增量清单。

#### 维度三：公式跨周期引用（G3，重要）

**根因**：架构上刻意保守——compat.rs:478 将 SECURITY/request.security 标记 HostRequired，要求宿主注入对齐数据，避免引擎内置重采样引入未来函数风险。这个决策正确但**没有提供默认宿主**，等于把安全成本转嫁给用户。

**影响**：跨周期引用是通达信 `#` 语法与 Pine request.security 覆盖的最高频场景之一。finkit 底层组件齐全（data_contract.rs 的 `TemporalSeries::align_to` 支持 Exact/AsOfClosed 闭市安全对齐、calendar.rs 交易日历、DirtyRange 局部重算），**缺的只是公式层语法糖 + 默认重采样宿主**。

**竞品实现**：通达信 `CLOSE#WEEK` 有"仅小周期引大周期、有未来函数风险"的官方限制；Pine request.security 文档明确 lookahead/merge 策略。finkit 有机会以"安全对齐、无未来函数"实现**代际超越**而非追平。

#### 维度四：因子研究产品形态（G4，重要）

**根因**：factor-analysis 的分析内核已追平 alphalens（IC/IR/分位/换手/衰减/事件研究/PSR 全有，见 analysis.rs:170/216/248/285、stability.rs:25/53、validation.rs:262/315），但 report.rs:71 仅 `to_json_pretty`。visualization crate（SVG/PNG/HTML 三档、decimate LOD、Crosshair 交互）与 factor-analysis **同 workspace 却零接线**。

**影响**：alphalens/quantstats/pyfolio 的共同产品形态是"一键 tearsheet"——这是因子研究的通用语言。finkit 组件齐全却交付 JSON，等于造好了发动机没装方向盘。

**竞品实现**：alphalens `create_full_tear_sheet` 一个函数输出全套图表矩阵；quantstats `reports.html(returns, benchmark)` 一行出 HTML 报表。

#### 维度五：数据生态互操作（G5，重要）

**根因**：polars_ext 定位为"可选 feature 的薄封装"（Cargo.toml:194，polars 0.46），TaSeries 仅 ta_sma/ta_ema/ta_rsi/ta_bbands 四方法，实现是提取 Vec<f64> → 计算 → 回写，无零拷贝、无 expressions/plugin。

**影响**：Polars 39.7k stars、月下载 3000 万+，是 Python 数据生态增长最快的底座；TA-Lib wrapper 已原生接受 Polars Series。finkit 的 polars_ext 现状无法承接这一生态位，且"零拷贝集成"的宣传（README.zh-CN.md）与实现（拷贝进出）不符。

#### 维度六：文档与生态（G6/G10，重要/次要）

**根因**：ADR 0011 将 rustdoc 覆盖策略限定在"public surface only"（core/src/lib.rs 注释），api-reference.md 手工维护仅 17 签名；无迁移工具与社区内容。

**影响**：320 个公式函数（含 DYNAINFO/DRAW 全族）是竞品没有的资产，但用户看不见。Pine 用 10 万社区脚本构建生态飞轮；通达信存量公式是国内最大迁移池。

## 第三部分：核心技术实现要点

### 要点 1：跨周期引用的安全实现（F2.1）

利用现有 data_contract + calendar，在公式层加语法糖，宿主默认提供重采样：

```rust
// core/src/formula/cross_period.rs（新增）
/// 跨周期引用的安全语义：
//  1. 仅允许小周期引用大周期（通达信限制一致）
//  2. 默认 AsOfClosed 对齐：只使用"已收盘"的大周期 bar，杜绝未来函数
//  3. DirtyRange 使历史修订只重算受影响区间
pub struct CrossPeriodHost {
    calendar: TradingCalendar,          // core/src/calendar.rs 已有
    frames: BTreeMap<Timeframe, MarketFrame>,  // data_contract.rs 已有
}

impl CrossPeriodHost {
    /// CLOSE#WEEK 的求值路径
    pub fn resolve(&self, expr: &str, tf: Timeframe, asof: i64) -> Result<TemporalSeries> {
        let weekly = self.frames[&tf]
            .resample(&self.calendar, tf)?          // 内置重采样（新增）
            .align_to(self.base_tf(), AlignMode::AsOfClosed)?; // 已有：仅取已收盘 bar
        // 未来函数防护断言：weekly 的最后时间戳必须 <= asof 所在大周期的收盘
        assert_no_lookahead(&weekly, asof)?;
        Ok(weekly.column(expr))
    }
}
```

公式层改动：parser.rs 增加 `IDENT#TIMEFRAME` 语法（通达信）与 `request.security` 的 Pine 映射（builtin_table.rs:241 已有占位）路由到 CrossPeriodHost，替换 compat.rs:478 的 HostRequired 短路。

### 要点 4：Alpha158 内置因子库（F2.3）

用 factor_graph 声明式定义，Qlib Alpha158 的算子×窗口矩阵直接映射：

```rust
// factor-analysis/src/builtin_factors/alpha158.rs（新增）
pub fn alpha158() -> FactorGraph {
    let mut g = FactorGraph::new();
    // KMID = (CLOSE-OPEN)/OPEN 类 K 线形态 9 个
    g.add("KMID", expr("(CLOSE - OPEN) / OPEN"));
    // 滚动算子×窗口：MA/STD/SLOPE/ROC/RANK/CORR × 窗口 5/10/20/30/60
    for w in [5, 10, 20, 30, 60] {
        g.add(format!("MA{w}"),  expr(&format!("MA(CLOSE, {w}) / REF(CLOSE, {w})")));
        g.add(format!("STD{w}"), expr(&format!("STD(CLOSE, {w}) / CLOSE")));
        g.add(format!("ROC{w}"), expr(&format!("REF(CLOSE, {w}) / CLOSE")));
        // ... CORR/ SLOPE/ RANK 等
    }
    g   // 158 个命名因子，全部走 FormulaHotPlan 编译复用
}
```

价值：每个因子自动获得 FactorPlan 编译复用 + DirtyRange 局部重算 + 9 语言绑定——这是 Qlib（Python 表达式逐条解释）结构上没有的执行层优势。

## 第四部分：总结陈述

未来 6 个月最核心的 3 件事：

1. **打通分发链路（F1.1/F1.2，4 人日）**——crates.io + PyPI 发布是所有后续工作的前提：没有标准安装路径，任何能力优势都无法转化为用户；ta crate 停更真空和 kand 的崛起决定了这个窗口以月计。

2. **把"组件齐全但未接线"的三个质变点交付掉（F1.5 tearsheet + F2.1 跨周期 + F2.2 polars accessor，约 23 人日）**——这三项的共同特征是底层组件全部存在（visualization/data_contract/calendar/polars_ext），只差最后一步产品化接线，却分别对应 alphalens 用户、通达信/Pine 用户、Polars 生态三个最大获客面。
