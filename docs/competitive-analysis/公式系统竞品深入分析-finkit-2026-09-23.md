# 公式系统竞品深入分析：通达信 / 大智慧 / TradingView Pine / 同花顺

> 生成日期：2026-09-23 · 调研方式：官方帮助文档 + 社区资料网络调研
> 对照对象：finkit formula 引擎（core/src/formula/，320 个内置函数，pest→AST→bytecode VM/HotPlan 双路径，4 终端方言路由 + Pine v5 子集）

---

## 1. 通达信公式系统（国内事实标准）

### 1.1 能力清单
- **函数规模**：数百个内置函数（行情/引用/逻辑/绘图分类），另有 60+ DYNAINFO 动态行情函数、L2 系列（L2_AMO 等，需 Level-2 权限）
- **语言能力**：序列第一公民；`:=` 中间变量、`:` 输出；**无用户自定义函数、无循环**；字符串能力弱（DRAWTEXT 常量文本、STR2CON、STKNAME、INSUM 板块统计）
- **绘图输出**：DRAWTEXT / DRAWICON（46 种图标）/ DRAWNUMBER / STICKLINE / DRAWKLINE + COLORXXX / LINETHICK / POINTDOT 线型修饰
- **选股与预警**：4 类公式（技术指标/条件选股/专家系统/五彩K线）；5 种选股器（条件/定制/模式/插件/综合）；条件预警盘中实时触发
- **多周期**：`#` 语法（`CLOSE#WEEK`、`KDJ.K#WEEK`），限制：仅小周期引大周期、仅基本数据、需本地下载、**有未来函数风险**
- **扩展**：专业版股票池（tpool XML 流程编排）、自定义数据管理器、DLL 机制（TDXDLL1-10 槽位，C 签名 `void f(int DataLen, float* out, float* ina/b/c)`）

### 1.2 finkit 现状对照（代码核实）

| 能力 | 通达信 | finkit | 差距 |
|------|--------|--------|------|
| 函数数量 | 数百（含 L2/DYNAINFO） | 320（DYNAINFO ✅、FINANCE/CAPITAL/WINNER/资金流 ✅、L2 仅 DKCOL） | L2 逐笔深度族缺失 |
| 绘图 | DRAW 全族 + 46 图标 | executor.rs 处理 DrawText/DrawIcon/StickLine/DRAWLINE/DRAWBAND/DRAWKLINE/DRAWRECTREL/FILLRGN/PARTLINE/POLYLINE/DRAWGBK/DRAWSL/DRAWTEXT_FIX/DRAWNUMBER/VERTLINE；drawing.rs 17 个 add_* | **基本追平** |
| 自定义函数 | ❌ | ❌（custom.rs 是表达式宏） | 持平（都无） |
| 跨周期 | `#` 语法（有未来函数风险） | SECURITY/request.security 映射存在但 **HostRequired**——需宿主注入对齐数据，无内置重采样 | **finkit 落后**（无开箱即用） |
| 选股/预警 | 5 种选股器 + 预警 | ❌（明确不做） | 定位差异 |
| 扩展 | DLL 槽位 | ffi_registry.json 基础 | finkit 更工程化 |

### 1.3 值得借鉴
1. **`#` 跨周期语法的开箱即用**：finkit 的 data_contract（TemporalSeries::align_to Exact/AsOfClosed）+ calendar 已具备安全对齐的全部组件，缺的只是公式层的语法糖与内置重采样宿主——**这是把"未来函数风险"变成"闭市安全对齐"的机会**。
2. **选股公式的场景化**：通达信一半价值在选股器/预警。finkit 虽不做选股引擎，但"条件表达式求值 + 批量标的扫描"（compute-many）是引擎层能力，可作为 CLI/服务形态交付。
3. **DLL 槽位的注册式扩展**：通达信用固定槽位让用户挂 C 函数；finkit 可提供注册式原生函数通道（已有 ffi_registry.json）。

## 2. 大智慧公式系统

- 函数与通达信同源同量级但**互不兼容**：大智慧特有 DYNAINFO/OPENINTEREST/HHVALL/LLVALL；通达信特有 ZXNH/DHIGH；社区维护函数对照表
- 特色：DDE 深度数据决策系统（DDX/DDY 逐单分析）、Level-2 十档/买卖队列/逐笔、SV 资金流向、AI 全链预警 + 策略因子交易平台（机构向）
- 语法：语句分号分隔、`:=` 中间变量，与通达信近似；DLL 接口签名与通达信不同

**对 finkit 启示**：大智慧的 DDE/资金流函数族（DDX/DDY/SV）与 finkit 已实现的 BIGORDER/MAININFLOW/NETINFLOW 有概念重叠，方言路由（compat.rs）已支持 EM 终端，补齐大智慧方言的边际成本低；其"策略因子交易平台"证明机构侧因子工作流有付费市场。

## 3. TradingView Pine Script（v5/v6）

### 3.1 能力清单
- **v6 代际升级**：更严格类型系统（series 泛型推断）、布尔短路求值、动态 request；类型含 int/float/bool/string/color/array/matrix/map、**用户自定义类型（UDT）**、方法、枚举
- **复用机制**：用户自定义函数 + **library 跨脚本复用**
- **数据引用**：request.security 多周期/多品种、request.economic 宏观、request.financial 财务
- **可视化**：plot/plotshape/plotchar/label/line/box/table/polyline/barcolor 全套
- **告警**：alertcondition/alert() 服务器端推送
- **生态**：1 亿+ 用户、**10 万+ 社区公开脚本**、内置 200+ 函数

### 3.2 finkit 现状对照
- Pine 兼容：builtin_table.rs 45 映射 = 34 个 ta.* + 6 math.* + request.security + na/nz/change——**v5 子集**
- 缺口：UDT/方法/枚举/matrix/map 类型系统、library 机制、request.economic/financial、动态 request、label/box/table 可视化对象

### 3.3 值得借鉴
1. **library 机制**：脚本导入脚本是生态飞轮的核心。finkit 的公式模板（templates.rs）+ custom.rs 可演进为"公式库"概念——命名、版本化、跨公式复用。
2. **类型系统演进路线**：Pine v5→v6 的"更严格类型 + 短路求值"证明公式语言需要类型检查而非纯动态解释。finkit 的 AST + contracts.rs 已有静态校验基础。
3. **request.security 的语义清晰度**：官方文档明确 lookahead/merge 策略——finkit 若做跨周期，应把"未来函数防护"作为一等公民文档化。

## 4. 同花顺公式系统

- 客户端公式：类 C 语法，四类公式与通达信对应；函数"大同小异"但不能直接照搬（**RSI/BOLL 口径差异**）；特有 ZJLR/ZJLC/ZLJZ 资金函数；导入格式 .tnc
- 问财：自然语言选股（"市盈率低于20的消费股"），且/或组合、限定词、策略保存——公式语言之外的低门槛入口
- iFinD：机构数据终端

**对 finkit 启示**：同花顺 RSI/BOLL 口径差异正是 finkit "多方言数值语义"架构（compat.rs 终端路由 + contracts.rs 契约测试）的用武之地——**"同一公式，按终端切换口径"是通达信/Pine 都做不到的**，应作为宣传点。问财的 NL 选股超出引擎定位，不做。

---

## 5. 对 finkit 的核心结论

1. **函数覆盖广度是硬差距但可控**：320 vs 数百，缺口集中在 L2 逐笔深度族与大智慧 DDE 族；DRAW 绘图族已基本追平。
2. **跨周期引用是最大功能缺口**：通达信 `#` 与 Pine request.security 都是刚需；finkit 有全部底层组件（data_contract/calendar/DirtyRange）但无开箱即用路径，且有机会以"安全对齐、无未来函数"实现超越。
3. **Pine v6 类型系统与 library 是中期方向**：UDT/matrix/map/library 决定生态上限。
4. **方言口径切换是独有卖点**：同花顺/通达信 RSI/BOLL 口径差异证明市场需求存在。
5. **生态差距最大且无法速胜**：Pine 10 万脚本不可复制，短期靠"通达信/Pine 脚本迁移工具 + 兼容性测试集"作为获客杠杆。
