# 因子研究竞品深入分析：alphalens / pyfolio / empyrical / quantstats / Qlib

> 生成日期：2026-09-23 · 调研方式：官方文档 + GitHub 网络调研
> 对照对象：finkit factor-analysis crate（prepare/validate/analysis/multifactor/portfolio/performance/report/risk_model/mining/scenario/session/executor/orchestration/incremental/stability/policy/evaluation_api）+ core 的 risk/returns/performance/features

---

## 1. alphalens / alphalens-reloaded（因子分析基准）

### 1.1 能力清单
- **核心 API**：`utils.get_clean_factor_and_forward_returns`（数据清洗枢纽）、`tears.create_full_tear_sheet` 及分项（returns/information/turnover/summary/event_returns/event_study）
- **performance 层**：mean_return_by_quantile、factor_information_coefficient、quantile_turnover、factor_rank_autocorrelation、factor_weights
- **分析维度**：IC 均值/标准差/IR（Risk-Adjusted IC）、分位收益（按日/按组/超额 demeaned）、分位累计收益、因子换手、因子自相关（alpha decay）、按 groupby（行业）分组及组内分箱（binning_by_group）、事件研究、多空组合权重
- **输入**：factor 为 MultiIndex(date, asset) Series，prices 宽表 DataFrame；参数 periods/quantiles/bins/filter_zscore/max_loss(0.35)
- **可视化**：matplotlib/seaborn 全套（分位收益柱状/violin、IC 时序热力图、换手曲线、累计收益）
- **维护**：原 quantopian 版归档；stefan-jansen/alphalens-reloaded 活跃，2025-06 发布 v0.4.5

### 1.2 finkit 对照（代码核实）

| alphalens 能力 | finkit 现状 | 证据 |
|----------------|-------------|------|
| IC/IR | ✅ | analysis.rs:170 information_coefficient；factor_metrics.rs:20 summarize_ic（icir/hac_t_stat） |
| 分位数收益 | ✅ | analysis.rs:216 |
| 因子换手 | ✅ | analysis.rs:248 + performance.rs:332 |
| 因子自相关/衰减 | ✅ | analysis.rs:285 rank_autocorrelation；stability.rs:25 estimate_half_life、:53 factor_psi |
| 行业分组 | ⚠️ 部分 | data.rs:126 add_group 通用分组 + analysis.rs:14 group_adjust（组内去均值/等权），**无内置行业分类表** |
| 事件研究 | ✅ | event.rs:16/57 |
| tearsheet 图表矩阵 | ❌ | report.rs:71 仅 to_json_pretty，无 HTML/图表 |
| 数据清洗枢纽 | ⚠️ | prepare 模块存在，但无 get_clean_factor 式单一入口 API |

### 1.3 值得借鉴
1. **`get_clean_factor_and_forward_returns` 单入口设计**：把"对齐+清洗+前向收益计算"收敛为一个函数，用户心智成本极低。finkit 的 prepare + data 模块可包装同等入口。
2. **max_loss 数据质量门禁**：清洗丢弃超过 35% 数据即报错——finkit 的 validate 模块可引入同等"数据质量预算"。
3. **binning_by_group 组内分箱**：行业中性化分析的标准操作，finkit 有 group_adjust 基础。
4. **tearsheet 图表矩阵**：IC 热力图 + 分位收益 + 换手曲线的组合视图是因子研究的"通用语言"。

## 2. pyfolio / pyfolio-reloaded（组合业绩分析）

- **核心 API**：`create_full_tear_sheet(returns, positions, transactions, benchmark_rets, live_start_date)`，分项 returns/transactions/positions/drawdown/rolling/exposure/bayesian
- **维度**：累计收益对比、滚动 Sharpe/波动/Beta、回撤分析、月度收益表、敞口（gross/net leverage、前十大持仓）、round trips（往返交易）、perf_attrib 因子归因
- **维护**：原版停更且不兼容 pandas 2.0；pyfolio-reloaded 2025-06 更新 Numpy 2.0 兼容

**finkit 对照**：finkit 明确不做回测，positions/transactions 维度超出定位；但**滚动统计（rolling Sharpe/vol/beta）、月度收益表、因子归因**与 factor-analysis 的 performance/portfolio 模块直接相关。finkit 已有 evaluate_benchmark（alpha/beta/treynor）、up-down capture，缺滚动窗口版本与月度聚合表。

## 3. empyrical（风险/收益指标库）

- **指标清单**：annual_return、annual_volatility、sharpe_ratio、sortino_ratio、calmar_ratio、omega_ratio、max_drawdown、downside_risk、value_at_risk、conditional_value_at_risk、tail_ratio、capture_ratio、up/down_capture_ratio、alpha、beta
- **工具函数**：cum_returns、cum_returns_final、**aggregate_returns（年/月/周聚合）**
- **维护**：quantopian/empyrical 2020-10 停更；empyrical-reloaded 社区接续

**finkit 对照（代码核实）**：

| empyrical 指标 | finkit | 位置 |
|----------------|--------|------|
| VaR/CVaR/MDD/Sharpe/Sortino/Calmar | ✅ | risk.rs（7 个函数） |
| annual_volatility / downside | ✅ | performance.rs:190/196 |
| omega / tail_ratio / capture / alpha / beta / treynor | ✅ | performance.rs:224/263/87/83/513 |
| ulcer_index | ✅ | performance.rs:56 |
| PSR / DSR | ✅ | factor-analysis/validation.rs:262/315 |
| **kelly_criterion** | ❌ | 未实现 |
| **aggregate_returns（年/月/周聚合）** | ❌ | returns.rs 仅 cumulative_returns |
| **cum_returns 系列** | ⚠️ | returns.rs:87 cumulative_returns 存在，无 final 变体 |

**结论**：finkit 的指标覆盖已达 empyrical 的 ~90%，缺口仅 kelly、aggregate_returns、cum_returns_final——**边际成本极低**。

## 4. quantstats（Pandas API + HTML 报表）

- **三模块**：stats（100+ 指标）、plots、reports（html/metrics/full/basic）；`extend_pandas()` 使 Series 直接 `.sharpe()`
- **特色指标**：ulcer_performance_index、gain_to_pain_ratio、kelly_criterion、payoff_ratio、profit_factor、consecutive_wins/losses、outlier_win/loss_ratio、smart_sharpe/sortino、**probabilistic_sharpe_ratio（PSR/PASR）**、risk_of_ruin、serenity_index、greeks、rolling_sharpe/sortino/volatility、implied_volatility
- **输出**：收益率 Series + benchmark → HTML/Excel 报表
- **维护**：ranaroussi 维护，社区广泛使用，更新节奏慢

**finkit 对照**：PSR/DSR ✅（validation.rs）、ulcer ✅；缺 gain_to_pain、kelly、payoff/profit_factor、连胜连败、smart_sharpe、risk_of_ruin、serenity、rolling 族、**HTML 报表**（report.rs 仅 JSON）。quantstats 证明"指标广度 + 一键 HTML"是业绩分析的产品形态。

## 5. Qlib（微软，因子工作流参考）

- **Alpha158**：158 因子 = 9 个 K 线形态（KMID/KLEN 等）+ 4 个价格 + 145 个滚动算子（MA/STD/SLOPE/ROC/RANK/CORR，窗口 5/10/20/30/60），全部**表达式定义**、价格归一化
- **Alpha360**：60 日原始 OHLCV + 60 个标准化收盘价，供模型学习
- **数据处理器**：DataHandlerLP 区分 infer_processors/learn_processors（RobustZScoreNorm 去极值标准化、DropnaProcessor），**预处理仅在训练区间拟合，机制上防前视偏差**
- **工作流**：data→handler→dataset→model→backtest

**finkit 对照与借鉴**：
1. **表达式因子库**：Alpha158 的"算子×窗口"矩阵式定义与 finkit 的 factor_graph（声明式 DAG）天然契合——finkit 可内置 Alpha158 等价因子集作为"开箱因子库"，每个因子是 factor_graph 节点组合。
2. **infer/learn 处理器分离**：finkit 的 features（normalization 防泄漏）已有同等语义，但未形成 DataHandler 式统一入口。
3. **防前视偏差的机制化**：Qlib 用"仅在训练区间拟合"表达；finkit 用 purged CV + point-in-time data_contract 表达——后者更严格，应文档化对齐。

## 6. 对 finkit 的核心结论

1. **因子分析核心指标已追平 alphalens**（IC/IR/分位/换手/衰减/事件研究全有），差距在**产品形态**：无 tearsheet HTML、无单入口 API、无内置行业分类表。
2. **风险指标缺口极小**（kelly/aggregate_returns/cum_returns_final/rolling 族），补齐成本 1-2 人日。
3. **报表是最大产品差距**：alphalens/quantstats/pyfolio 的共同形态是"一键 tearsheet"；finkit report.rs 仅 JSON 输出，而 finkit 恰好有 visualization crate（SVG/PNG/HTML 三档渲染）——**组件齐全但未接线**。
4. **Qlib 式内置因子库**是低成本高感知的差异化：Alpha158 用 factor_graph 表达式化后即是"开箱因子库"。
5. **非 Python 因子研究市场空白**：alphalens/pyfolio/quantstats 全部 Python-only，finkit 的 9 语言绑定 + factor-analysis 组合可独占 Node/Go/Java/.NET 因子研究场景。
